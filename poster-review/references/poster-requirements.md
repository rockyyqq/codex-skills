# Poster requirements checklist

Accumulated from the user's instructions across poster work. Treat every line as a requirement unless the
user says otherwise for a specific poster.

## Deliverable

- [ ] Primary output is an editable PowerPoint file with native text and shapes.
- [ ] Print PDFs exported from the same content at each size the event requires.
- [ ] New filename for every version; no earlier version overwritten.
- [ ] The submission copy is named and identified in a read-me so it cannot be confused with alternatives.

## Structure

- [ ] Section order is Background, Methods, Participants, Results, Discussion.
- [ ] Participants come before Results.
- [ ] The programme or intervention content is described session by session, not summarised in one line.

## Writing

- [ ] Prose for Background and Discussion; bullets for Methods and list-like blocks.
- [ ] No section converted wholesale to bullets, and none left as a wall of text.
- [ ] Rationale grounded in the author's own prior published work, with citations.
- [ ] Limitations and caveats kept, so the claims survive questioning.

## Emphasis

- [ ] Satisfaction and acceptability highlighted in a callout.
- [ ] That callout sits with the results, not at the top of the poster.

## Design

- [ ] No conspicuous empty regions; the page reads as filled.
- [ ] Type sized to fill the layout, and legible at the delivered size.
- [ ] Visual theme reflects the subject matter rather than being a stock template.
- [ ] No slope chart for a many-item pre-post comparison.
- [ ] Comparison chart style chosen from options rather than assumed.

## Data

- [ ] Every count sums to n; every percentage column sums to 100.
- [ ] Free-text "Other" responses broken into named categories.
- [ ] Categories combined only on request.
- [ ] Every figure traceable to a named source file.

## Compliance

- [ ] Page sizes and orientation exactly as specified by the event, verified in millimetres.
- [ ] Required identifier printed in the required position.
- [ ] Deadlines recorded, and which artifact is due when.
- [ ] Print production constraints respected: lamination, no mounting, bleed and safe margins.

## Verification

- [ ] An independent verifier has checked the PowerPoint file itself.
- [ ] The verifier brief is read-only and forbids subagents and redesign.
- [ ] Findings carry what, where, evidence, confidence and severity.
- [ ] Any area that could not be verified is stated as unverified rather than implied to be checked.
