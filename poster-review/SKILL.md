# Poster Review

The user's standing requirements for poster work. Apply them to every poster request without being asked
again. Read [references/poster-requirements.md](references/poster-requirements.md) for the full checklist
and [references/build-mechanics.md](references/build-mechanics.md) before building, since several of the
mechanics have already caused defects once.

## Output format - non-negotiable

- The deliverable is a **PowerPoint file** built from native objects: real text boxes, shapes and lines.
  Not a flattened image placed on a slide, and not a PDF on its own. The user edits the deck afterwards.
- Where the poster is also going to print, export print PDFs from the same content at the sizes the event
  requires, and keep the deck and the PDFs in step when wording changes.
- Every version gets a **new filename**. Never overwrite an earlier version.

## Section order

Background, then Methods, then Participants, then Results, then Discussion. The participant and
sociodemographic panel sits **before** Results, not after.

## Text treatment

Use a mix, deliberately:

- **Prose** where the content carries an argument - Background and Discussion.
- **Bullets** where the content is genuinely a list - Methods, and the session or programme block.

Do not convert every section to bullets, and do not leave every section as a dense paragraph. The user
asked for more bullet points and then had to correct an over-application of exactly that.

## Acceptability and satisfaction

Highlight satisfaction and acceptability figures in a callout, but **not** at the top of the poster. Put
the callout with the results, so a reader meets the evidence before the summary.

## Layout and legibility

- Leave no conspicuous empty space. Content should fill the page; check for blank bands by measuring the
  rendered page, not by eye.
- Prefer larger type that fills the layout over small type with gaps. Chart labels must stay readable at
  the delivered size.
- A poster that is printed or projected must be checked against its rendered output, never only against
  the source file.

## Charts

- Do **not** use a slope chart or slopegraph for pre-post comparisons when many items are shown; the user
  finds the crossing lines messy.
- Offer comparison style choices before committing - for example dumbbell, delta bars, paired columns,
  arrow list, restricted slopegraph, or radial.
- Keep data charts as native editable objects rather than images.

## Data handling

- Every count must sum to the stated n, and every percentage column to 100.
- Where a questionnaire collected free-text "Other" responses, break them into named categories.
- Combine categories only when the user asks for it.
- Enrich the rationale from the author's own prior published work where it exists, with proper citations,
  rather than reaching for generic background.

## Academic rigour

- Every number and claim on the poster traces to a named source file.
- Do not overstate. Keep the direction and magnitude of findings as the source reports them.
- Anticipate the questions a judging panel would ask, and make sure the poster and any talk track can
  answer them.

## Verification - mandatory, and it targets the PPTX

- An **independent verifier** must check the **PowerPoint file** before delivery, not only the PDF.
- Write the verifier's brief so it is read-only. Say explicitly: do not create, edit, move or delete any
  file other than its own report; do not spawn subagents; do not redesign or re-export the deck. Two
  earlier verification runs wrote unrequested files into the deliverable folder; that must not recur.
- Require evidence per finding: what, where (slide and object id, or file and page), what it was checked
  against, confidence, and severity.
- If the independent pass does not complete, say so plainly rather than implying the work was verified.
